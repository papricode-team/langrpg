# HUD second visual pass

Implemented the target HUD composition with main's existing painted brass, enamel, parchment and leather kit. Read `AGENTS.md`, `docs/style/art-direction.md`, the first UI pass and the visual-style review; viewed the target at full size and zoomed its minimap/chapter area before implementation. Character style, camera framing and the kit's materials remain the agreed direction.

## What changed

- Player portrait/nameplate now carries the name, an earned title (initially “Wanderer of the Atlas”), the actual active course and level, XP and chapter progress. Character editing still opens from the portrait. Copy was fitted to the painted plate's narrower central band.
- The existing parchment town banner now has W · N · E above the Fraunces town name. It uses the authored town subtitle rather than inventing an unrepresented district. Arrival animation and indoor place names are preserved.
- Help, fullscreen and sound use the existing round painted buttons at top right and their existing actions. Sound's pressed state and glyph update when toggled.
- New round minimap uses `getMap(mapId).previewAsset`, `sceneDocument.maps[mapId]` dimensions/anchors, names from the loaded NPC/expedition registries and `World.getPlayerPosition()`. The same cover projection maps the painting and coordinates. A gold player marker moves through the existing `World.onFrame` subscription; cream resident dots have actual names in titles and accessible labels. Position updates retain DOM/control focus. The map hides indoors.
- The desktop chapter card adds the current quest title, next objective, first authored learning objective, actual completed/total stories and quest XP reward to the existing story beacon. “Continue story” uses its existing `next-objective` action. Complete chapters do not promise the quest reward again. Indoor exits and expedition actions retain their existing compact beacon rather than borrowing unrelated chapter data.
- The bottom dock opens the existing Quests, Journal, Atlas, Character and Settings pages. Q/J/M/C/O hints match existing shortcuts. The Journal retains the due-review dot. Movement hints sit above it on desktop.
- Bottom left is a real **local presence** panel: current place, connection status and other players in that map/interior, with a truthful empty state. There is no chat composer or invented transcript.
- Bottom right counts actual `dueItems(progress)` as “words ready to revisit” and invokes the existing review action. It hides when none are due.
- At shared tablet/short-landscape breakpoints, the minimap/presence/revisit panels disappear and the chapter card becomes the painted story beacon. On phones the dock becomes a tab bar and sits below the existing touch controls. Long tab/course/name labels truncate without shrinking type. Narrow landscape uses reduced beacon chrome and hides the decorative lantern meter; the story action remains available.
- The existing lantern meter moved to the left desktop edge above presence, and to the right phone edge below the header; account/admin overlays were repositioned to clear the new frame. Dialogue/cinematics hide the HUD additions. Painted controls keep no ordinary focus ring and retain forced-colours outlines. Text stays at or above 12 px (phone captions use the existing 13 px token).

## Adaptations and work needed elsewhere

1. **Chat:** this client has presence snapshots, not a backed chat interface. The lower-left panel exposes that real presence. A functioning local chat would require a separate server/client feature; none is fabricated here.
2. **Live residents:** cream dots are explicitly labelled “resident meeting places,” using published anchors. Roaming NPC positions are private to the scene. To make them live without HUD code inspecting Phaser internals, the scene owner can expose `World.getNpcPositions(): readonly { id: string; x: number; y: number }[]` in canonical scene units (including current story NPC positions), then the HUD can project those values. No scene files were edited.
3. **Recentre:** no public camera-recentre action exists. The compass honestly opens the region atlas. If desired, the scene owner can add `World.recenterOnPlayer(): void`, respecting watch/dialogue/cinematic modes; then this button can invoke it. It is not currently labelled as a recentre action.
4. **Review terminology:** the existing review queue is word memory, so the prompt says “words,” not an invented separate memory collection. Chapter totals come from current quest data and may differ from the mock's illustrative six.
5. **Localisation:** new HUD copy is routed through `t()` but falls back to English where a UI overlay has no entry. Read-only inspection of `web/src/data/i18n/tr-ui.json` confirmed these missing Turkish UI keys: “Wanderer of the Atlas”, “Town map · resident meeting places”, “Local presence”, “Local”, “Adventure menu”, “Click to wander”, “You are exploring this place.”, “{count} words ready to revisit”, “{done}/{total} stories discovered”, “Continue story”, “Chapter {number}”, “Game controls”, “You are here” and “Sound”. The localisation owner should supply those translations and check the German overlay too. Locale files are outside this agent's ownership.
6. **Final rendering QA:** coordinator should inspect live desktop, 601–1000 px widths, 320/390 px phones, short landscape, long names/localised copy, access/admin overlays, fading-name/lantern states, fullscreen/audio, indoor exits, expedition beacons and forced colours against the new camera. Static checks and composites cannot certify browser layout or event routing. The latest narrow-landscape rule specifically prevents header-plate overlap; that state has no browser screenshot here.

Remaining integration work is localisation and browser review as detailed above. The scene accessors are optional enhancements; the delivered HUD uses published meeting places and opens the real atlas. No commits or git-state changes were made.
