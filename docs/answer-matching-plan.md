# Answer matching: accepting more than one right answer

Status: layers 1 and 2 implemented on 2026-10-17. Layer 3 (attempt mining) and the nearest-form feedback are not built. Section "What was built" at the end records where the implementation differs from this proposal.

## The problem

Production exercises (`type` and `sentence`) are graded by comparing the player's text against `answer` plus a hand-written `acceptedAnswers` list, after normalisation (NFC, whitespace, trailing `.!?`, case, `ae/oe/ue`, one mechanical typo in a word of five letters or more). The code is `Exercise.Grade` in `server/curriculum.go`, mirrored by `answerMatches` in `web/src/learning.ts`, with `server/grading-fixtures.json` proving parity.

That machinery is fine for the single-word drills, which are most of the bank. It fails on sentences, because German sentences have several correct forms and we author one:

| Bank | Production exercises | Multi-word | Multi-word with any alternative |
|---|---|---|---|
| story quests + course | 3,557 | 274 | 50 |

Of the 50 that have alternatives, nearly all are punctuation or `noch mal`/`noch einmal` variants. The 1,827 single-noun drills get `die Wohnung`/`Die Wohnung` generated by `scripts/build-course.mjs`. Nobody has authored the variants that actually come up:

- **Pronoun for a named subject.** Prompt: "Say the bicycle is new." Authored: `Das Fahrrad ist neu.` A player who writes `Es ist neu.` is marked wrong. Twenty sentences start with article + noun and have this problem.
- **Vorfeld shifts.** `Der Zug fährt um acht Uhr.` vs `Um acht Uhr fährt der Zug.`
- **Digits and number words.** `um 8 Uhr` vs `um acht Uhr` (authored by hand for one exercise, nowhere else).
- **Contractions.** `zu dem` / `zum`, `an dem` / `am`, `in das` / `ins`.
- **Optional politeness and its comma.** `Noch einmal, bitte.` / `Bitte noch einmal.` / `Noch einmal bitte.` (four variants listed by hand today).
- **Lexical near-synonyms the course teaches.** `Ich möchte …` / `Ich hätte gern …`, `ein Kilo` / `ein Kilogramm`.

The `sentence` (tile) mode has the same bug from the other side: `sentenceTiles` in `web/src/learning.ts` adds pronoun and connector distractors to the tray, so a player can build a sentence that is correct German and still be told it is wrong.

## What we are not going to do

- **Grade with a language model.** The project rule is that nothing at runtime derives correctness from text and no external service is involved (`docs/content-server-language-plan.md`). Grading has to be deterministic, offline-testable, identical in Go and TypeScript, and explainable in the feedback line. A model grader breaks all four and would also make `grading-fixtures.json` meaningless.
- **Fuzzy similarity thresholds.** `Ich trinkt Kaffee` is one character from correct and is wrong. Edit distance cannot tell a slip from a grammar error; the current typo rule is deliberately narrow and should stay so.
- **Ignore the subject, verb or any word class.** The exercise exists to make the player produce a specific lexeme (`itemId`, `targetWordId`). Any accepted variant must still contain it.

## The method

Three layers, each deterministic, each tested by fixtures in both runtimes. Together they replace "one string must match" with "the answer must be one of a finite, authored, lexeme-preserving set".

### 1. Course-wide equivalences, declared in content

Some variants are a property of German, not of an exercise. Add an `equivalences` list to the course `grading` block (`contentstore.Grading`, next to `keyboardSubstitutions`):

```json
"equivalences": [
  {"group": ["zu dem", "zum"]}, {"group": ["zu der", "zur"]},
  {"group": ["an dem", "am"]}, {"group": ["in dem", "im"]},
  {"group": ["in das", "ins"]}, {"group": ["an das", "ans"]},
  {"group": ["noch einmal", "noch mal", "nochmal"]},
  {"group": ["Kilogramm", "Kilo", "kg"]},
  {"numbers": true}
]
```

Grading rewrites both the player's text and every accepted form to the first member of each group before comparing, token-wise, after the existing normalisation. `numbers: true` maps `0`–`100`, `tausend`, and clock forms (`8 Uhr`, `8:30`, `halb neun`) to their number words with one table. Punctuation inside a sentence (`Noch einmal, bitte`) is dropped at this step; it is already dropped at the end.

This layer is cheap, applies to all 274 sentences at once, and has no authoring cost. It is also where the German-specific knowledge belongs: the English proof course declares an empty list and nothing changes for it.

### 2. Per-exercise answer patterns, expanded at build time

For variants that depend on the sentence, replace the hand-written `acceptedAnswers` list with one `answerPattern` string using a small, fixed grammar:

| Syntax | Meaning | Example |
|---|---|---|
| `{A\|B}` | exactly one of | `{Das Fahrrad\|Es} ist neu.` |
| `[X]` | optional | `Ich nehme das Brot[, bitte].` |
| `<A ~ B>` | either order of two adjacent clauses | `<Um acht Uhr ~ fährt der Zug>` is not enough on its own, see Vorfeld below |
| `@pron` | the pronoun for the preceding noun's gender, from the lexicon | `{Das Fahrrad\|@pron} ist neu.` → `Es` |

The build (`scripts/build-story-curriculum.mjs` for quests, `scripts/build-course.mjs` for the course) expands each pattern into a flat list and writes it to the existing `acceptedAnswers` field of the server manifest. **The Go and TypeScript graders do not change for this layer**; they keep comparing against a list. That keeps the runtime small and the fixtures valid. The build enforces:

- the authored `answer` is one of the expansions;
- every expansion contains the target lexeme (lemma or a surface form from `course-lexicon.json`), so `Es ist neu` is accepted for an exercise whose target is `neu` and rejected by the build for one whose target is `Fahrrad`;
- at most 64 expansions per exercise, so nobody writes a pattern that accepts everything;
- `sentence`-mode `tokens` are derived from the canonical answer as today, and every tile in `sentenceTiles` that can form an expansion is added to the tray so that building a correct variant is possible, and building a wrong one stays wrong.

For Vorfeld shifts the pattern grammar gets one rule rather than a general permutation: `^{Der Zug fährt um acht Uhr | Um acht Uhr fährt der Zug}` is written by the author, because not every fronting is natural and the author should decide. The build helper can propose the fronted form for review, but it does not generate it silently.

`acceptedAnswers` stays supported for exercises that have one; the build merges both. New authoring uses the pattern.

### 3. Candidates from real attempts, approved by a reviewer

The server already stores every attempt request with its answer text (`attemptRequest` in `server/internal/store/model.go`). Add an admin report, `node scripts/answer-candidates.mjs`, that groups wrong answers per production exercise, drops anything the current grader already explains (capitalisation, article, word order, umlaut), and lists the remaining distinct wrong answers given by at least three accounts, with counts. A reviewer turns a row into a pattern edit or leaves it. This closes the loop: the list of accepted forms grows from what players actually write, never from a guess at runtime, and every addition passes through a human and through `npm run release:check`.

## Feedback

`gradeFeedback` compares a wrong answer against `exercise.answer` only. Once there is a set, compare against the nearest accepted form (fewest differing tokens) so that a player who tried `Es ist neue` is told about the adjective ending, not that they should have started with `Das Fahrrad`. The server's `Exercise.Feedback` mirrors this.

## Rollout

1. Layer 1 in Go and TypeScript with fixtures for every equivalence group. The German course declares the list; the English proof declares none. The 274 sentences gain the mechanical variants with no content edits.
2. Pattern expander as a Node module with its own tests, wired into both build scripts; the drift check in `scripts/verify.mjs` catches a manifest that was not regenerated. Convert the 50 exercises that already have `acceptedAnswers` into patterns, confirm the expanded lists are a superset of what was there.
3. Author patterns for the 20 article-plus-noun sentences and for the exercises whose prompt leaves the form open ("Order a coffee politely", "Ask if there is a room free"). Each pattern is reviewed as content.
4. Attempt-mining report. Run it against production once a week and feed the result into step 3.

Layers 1 and 2 need no schema or migration; the manifest and the content bundle are regenerated files. Nothing changes for choice, listen, recognition or listening exercises, which stay exact.

## What was built

**Layer 1.** `contentstore.Grading` gained `ignoreInner` and `equivalents`. The German values live in `web/src/data/grading-equivalents-de.json`; `scripts/build-content.mjs` copies them into the course configuration, `courseGrade` in `server/content_runtime.go` applies them, and `answerMatches` in `web/src/learning.ts` reads the same file. Seventeen new cases in `server/grading-fixtures.json` run against both graders; the Go fixture test now also checks every fixture's expected result against the configured grader. Fixtures marked `courseRule` are skipped only in the comparison with the older unconfigured Go grader, which tests still use.

Differences from the proposal:

- **No contractions.** `zum` / `zu dem`, `am` / `an dem` and the like are not equivalents. Fixed expressions (`zum Beispiel`, `am besten`) and relative clauses (`das Haus, in dem`) allow only one form, so a course-wide rule would pass grammar errors. Where both forms fit, an exercise pattern can list them.
- **Numbers are word-level, without clock forms.** Digits and number words from 0 to 100 are equivalent, matched with umlaut keyboard spellings (`fuenf`). `8:30` / `halb neun` is not handled. `1` maps to `eins` only, never to the article `ein`.
- **Equivalents need two or more words.** A one-word answer keeps its exact spelling, so a drill for `acht` does not accept `8` and one for `gern` does not accept `gerne`.
- **Inner punctuation is part of the configuration**, not stripped unconditionally, so the English proof course grades exactly as before.

**Layer 2.** `scripts/answer-patterns.mjs` expands `{A|B}` and `[optional]`. `build-story-curriculum.mjs` and `build-course.mjs` merge each exercise's literal `acceptedAnswers`, any entry written as a pattern, and its `answerPattern` into the manifest. Both builders now also update the manifest snapshot under `legacyServer` in `content/source.json`, which the content bundle grades from; earlier commits kept that copy in step by hand. A tooling test fails when the two drift.

Thirty-nine story exercises have patterns, including `Wann ist {das Fahrrad|das Rad|es} fertig?` and a fronted `Um acht Uhr fährt der Zug`. Each keeps the chunk its hint teaches; for example `Ist die Rückfahrt im Preis enthalten?` does not accept `inbegriffen`. Ten exercises whose literal lists only spelled out comma and synonym variants now use a pattern instead; a one-off check graded every previously accepted answer with the browser grader and none was lost. Two course writing tasks use pattern entries.

Differences from the proposal:

- **No `@pron`.** Authors write the pronoun. Choosing `es`, `er`, `ihn` or `ihm` needs case as well as gender, and the prompt decides whether a pronoun answers it at all: the story's literal prompts such as "Say: 'The room is quiet.'" name the noun, so they did not get one.
- **The target-word check runs only where an exercise names a target.** Story exercises have no `targetWordId`, so their patterns are reviewed as content.
- **Sentence tiles are unchanged.** Tile trays still hold the canonical tokens plus distractors, so a tile exercise accepts an alternative only if its tiles can build it.

Still open: layer 3, the attempt-mining report, and feedback that compares a wrong answer with the nearest accepted form rather than the canonical one.
