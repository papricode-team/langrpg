**User requirement:** all new terrain follows this high-resolution format: 4 texture pixels per world unit, 768 × 512 logical chunks, 3072 × 2048 visible texture pixels plus guard bands, and ≤2 MiB per file. Expanded 3072 × 2048 worlds therefore represent 12288 × 8192 artwork per lighting state. Follow [the detailed terrain source workflow](../art/source/terrain-detail/README.md). The station-yard, parcel-yard, garden-court and canal-walk additions each use eight native close-up paintings, with exact prompts, LFS rules and a bounded exporter; see [expansion sources](../art/source/terrain-expansion/README.md). Their day/night detail and overview assets are now registered in the canonical scene. The scene compiler rejects expansion chunks that omit the required density, size, lighting states, overviews or guarded crops; the build budget enforces file sizes. Lower-resolution layouts remain references only.

Templates include café terraces, market corners, parcel depots, gardens, forest clusters, harbor work areas and sheltered benches. Updates show object and activity changes; source edits never silently update other copies. Catalog and copy metadata survive drafts and Tiled exchange. Deleted child IDs remain reserved, and scatter proposals become invalid after scene edits.
- All 13 regions have Tiled v2 exchanges for geometry, scenery, terrain, activities, owner-relative entrances and generation metadata; explicit legacy v1 import remains available.
- Server/client handshake rejects incompatible dimensions or content versions; local development server restarts when embedded authority files change.
- Owner-relative doors for all twelve story-town entrances: moving a storefront moves its entrance and return together. The compiler requires exact reachable approach/return points; the server and browser use the compiled return. Removing a door owner is blocked until reassignment, and regeneration preserves owners of doors or activities.
- Durable world epoch/seed in both JSON and PostgreSQL storage; server packets carry elapsed time and the twelve-minute-day contract. Connected residents reconstruct seeded routines directly from shared time, including closing-time travel home. Small clock corrections blend without reverse travel; reduced-motion presentation and manual/local sky previews do not alter connected resident state or availability checks. Legacy resident routes also honor an explicit core origin offset.
- Authored resident homes and daily visits to owner-relative activity positions. The editor can add residents and time blocks, choose actions, durations, held objects and fallback positions, and sample a schedule guide at a selected hour. Draft validation checks references, exact home/activity reachability, distinct capacity positions and sufficient round-trip travel time. Deletion and prefab updates protect positions used by schedules. Tiled exchanges retain the same resident definitions.
- A deterministic daily plan reserves physical positions across residents and activity IDs. A full position makes the resident wait at home, use an authored fallback or skip the visit; every accepted visit returns home before its time window closes. Routes compile once and frame updates sample the shared clock. Two day plans are cached, so late joins and offscreen actors reconstruct without replaying previous frames. These are ambient client plans, not authoritative inventory transactions.
- Latest-main terrain renders in editor and game without scaling the original district; a doubled-bounds rendering test checks that existing chunks stay fixed.
- Shared terrain residency in game and editor: two concurrent requests, reference-counted texture leases, stale destination eviction, failure retry, 1px/world overview LOD and camera-local 4px/world detail capped at 32 million visible texture pixels per terrain layer. Day/night crossfades temporarily retain both layers. Entering an interior releases outdoor terrain. The 16-chunk test keeps fit-to-world ground at 24 MiB RGBA and detail plus previews below 150 MiB per layer.
- Supported connected-area audit and independent expansion gate: `npm run worlds:check-expansion` requires every original map to reach 3072 × 2048 and twice its original spawn-connected cell count. The updated measurement exactly reproduces all 13 immutable baseline counts. This gate correctly still fails: Lindenhafen now passes width and connected area, but its height remains 1536; the other twelve maps still need their expansions.

The editor is available through `npm run dev` at `/editor.html`. It is deliberately excluded from the production bundle and its save endpoints exist only in Vite development mode. This worktree's preview uses ports 5197/8197 to avoid the separate main checkout's services on 5187/8097.
